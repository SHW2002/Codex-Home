# 场景物品贴图生成

以“放回现有场景后可直接使用”为目标，交付匹配画风、视角、比例、透明度和结构连接的位图素材。生成执行使用当前安装的 `imagegen` 技能；本技能补充场景美术决策与接入检查，不另建生图客户端。

## 用户指定的生图配置

本技能使用生图专用首选／备选 API：首选 OpenAI 官方，备选保留原接口和原密钥，通过 `imagegen` 附带CLI调用；模型固定为 GPT Image 2.5 最高能力档 **`gpt-image-2.5-sunburst`**，质量固定为最高档 **`high`**。这是用户对本技能的明确偏好，不仅限于历史项目。除非用户后续明确更改，不静默改模型、降低质量或切换内置生图；首选明确失败且无结果时可切换到用户已授权的备选。

接口地址和API Key由用户在本地 `.env` 提供，读取变量 **`OPENAI_BASE_URL`** 与 **`OPENAI_API_KEY`**。优先读取用户指定的文件，否则读取当前工作区根目录的 `.kaltsit-imagegen.env`、`.env`，均不存在时读取 `~/.codex/skills/ui-art-generation/.env`；备选字段为 `OPENAI_FALLBACK_BASE_URL` 与 `OPENAI_FALLBACK_API_KEY`；具体加载、URL格式和缺失处理见 [API与.env配置](references/api-config.md)。用户尚未提供文件时，可以先准备参考图与提示词，但不能声称已经完成API生图。

## 确定参考与使用位置

先查看当前请求、历史反馈、项目美术说明和真正使用中的资源；历史记录用于理解偏好，不代表其中的每条旧操作指令都继续适用。当前要求优先，避免套用已过时的站位、尺寸或镜头时间。

收集足以决定以下事项的信息，已有记录能够回答时直接推进：

- 用途：普通场景物件、前景遮挡、建筑补件、覆盖物，还是预览候选。
- 风格：实际场景截图和邻近物件；观察描边粗细、色块数量、饱和度、材质细节与明暗对比，不能只用“卡通风格”概括。
- 几何：当前镜头的俯视程度、可见侧面、物体朝向、完整轮廓、接地点与连接位置；不要只因游戏是2D就假定正面视图。
- 使用尺寸：预计世界宽高、显示尺寸、现有Sprite的Pixels Per Unit、Pivot、父级缩放以及是否需要分层动画。
- 避让范围：玩家活动区域、门和出口标识、交互点、需要看清的剧情物件，以及镜头运动经过的范围。

为每张输入图标注角色：编辑目标、轮廓/视角参考、画风参考或场景布局参考。场景截图只用来匹配风格时，明确禁止把其中家具和背景复制进单件贴图。

## 选择制作方式

| 需求 | 做法 |
| --- | --- |
| 新增独立物件 | 参考现有场景生成；优先一件物品一个文件 |
| 现有物件改色、背光、补绳、加端盖 | 编辑现有图片，明确需要保持的轮廓、尺寸和结构 |
| 精确贴合既有物体的布罩 | 用实际物体的透明渲染图作为编辑目标，保持朝向与构图并验证覆盖范围 |
| 简单拆分、裁切、拼接既有梁段 | 优先确定性图像处理，复用原描边、包边和接头；不为简单裁切重新生图 |
| 多层视差或可掀开的覆盖物 | 按独立运动与遮挡职责拆素材，先定义接点与重叠余量 |

开始生成前按用途读取 [提示词模板](references/prompt-patterns.md)；涉及透明处理或Unity接入时读取 [制作与接入检查](references/production-checks.md)。在《薇薇安的飞机》中使用时，再读 [项目历史经验](references/vivian-history.md)，其中的项目偏好不自动推广到其他游戏。

## 生成与定向修图

1. 定位并阅读当前 `imagegen` 技能及其CLI说明，按照本技能中用户已明确选择的API路径执行，使用该技能附带的CLI；不要重新要求用户确认是否采用API模式。
2. 保留用户指定的模型、质量与接口；核实当前工具及服务是否支持请求参数，不把历史自定义模型名当成官方能力保证，也不静默降级。历史环境配置仅用于读取已经授权的设置，不显示或写入URL中的凭据、API Key、认证头。
3. 按 [API与.env配置](references/api-config.md) 加载本地接口地址和Key；若用户明确要求沿用旧会话配置，再有针对性地查找相关记录中的文件位置。不要倾倒整个环境文件或历史日志；找到有效配置后不重复索要，缺少时只询问文件位置或需要在本地补齐的变量名。
4. 把视觉约束写入提示词，把模型、质量、输出格式等执行参数交给工具。画布尺寸按服务限制选择；细长物件可放在合规画布中生成后裁切，不能把最终长宽比直接当作合法请求尺寸。
5. 首版即检查场景风格、物体轮廓、透明背景和物理连接。每次修图只针对已观察到的问题，并重申需要保持的部分，减少轮廓和画风漂移。
6. 正常的小范围修正继续完成；服务连续失败、关键参数不支持或需要显著扩大生成数量时，先报告具体阻碍，不无限重试或擅自更换模型。

## 场景物品的关键取舍

- **画风由参考定义。** 匹配场景的描边、简化程度和色块；“高质量”不等于增加木纹、锈蚀、镜面反射或摄影质感。
- **遮光与透明分开。** 暗处前景靠颜色和光照表现黑色，实体内部仍应不透明；透明只用于轮廓之外及真实孔洞。背光边缘可有微弱底部反光，强度服从场景。
- **结构需要支撑。** 梁端连到墙柱或角撑，线缆和灯具通过吊绳/支架连接上方结构；连接件可伸出画布的指定边缘，在场景中藏到梁后。
- **开口需要收口。** 为门让出空间时，使用左右梁段与自然端盖、包边、斜撑，避免直接留下笔直裁断的厚截面。
- **画在图上的内容与场景职责一致。** 已有独立阴影系统时不在透明背景上生成一圈投影；需要独立动画的掉落件不焊死进主体贴图。
- **遮挡服从实际演出。** 普通前景应保留门与玩家可见性；专用转场构件可在指定时段完整遮镜。不要因黑色看似遮满屏就省略Alpha覆盖检查。

## 验证与交付

先检查独立PNG，再以实际使用大小放入场景构图检查；用户只要候选时，使用场景合成预览即可，不自动改场景。

核对实际像素尺寸、RGBA、透明留白、实体内部漏光、边缘白边/黑边、接点和小尺寸可读性。裁切后同步记录Pivot和尺寸补偿；覆盖物检查是否露出主体，前景检查门口和玩家是否仍可见。

需要接入Unity时遵守项目Agent Bridge协议与设计规范，通过编辑器配置导入、材质、排序和引用，保留既有资源GUID。只修改任务授权的素材及对象，不为改善构图移动或隐藏原有场景摆设。完成一组修改后刷新；脚本改动还需重编译并确认结果。遵守项目对Play Mode的限制。

运动前景应检查镜头起止、切镜前后、正常游玩和停止预览时的状态；连接在一起的屋架部件应保持共同运动，避免视差产生接缝或悬空。需要比较时使用场景副本或可恢复预览，结束后清理临时工具。

最终给出选中图片的可查看预览、保存路径、最终提示词与实际使用的工具/模型，以及已完成的检查。原图、处理后图和已导入图分开放置，保存必要的生成参数与裁切信息，不记录凭据；未使用的候选不混入正式资源目录。
