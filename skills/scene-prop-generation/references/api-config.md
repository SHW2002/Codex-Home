# API与.env配置

## 固定的用户要求

| 项目 | 默认要求 |
| --- | --- |
| 调用方式 | 生图专用：首选 OpenAI 官方 `https://api.openai.com/v1`，备选原接口；使用当前 `imagegen` 技能附带CLI |
| 模型 | `gpt-image-2.5-sunburst`，实际请求必须显式指定，不能依赖CLI默认模型 |
| 质量 | `high`，用户要求最高档，不能用草图理由降为low/medium/auto |
| 服务地址 | 从本地 `.env` 的 `OPENAI_BASE_URL` 读取 |
| API Key | 从同一 `.env` 的 `OPENAI_API_KEY` 读取 |
| 素材输出 | PNG；需要独立Sprite时验证真实透明Alpha与实体不透明度 |

当前新请求可以明确覆盖这些偏好。`.env` 中的其他业务配置和历史默认值不能暗中覆盖模型与质量。`gpt-image-2.5-sunburst` 是用户指定服务的模型标识，服务和CLI是否支持其参数仍需核实；报错时保留这一要求，说明具体限制，不自行换模型。

## 首选／备选规则

`OPENAI_BASE_URL`、`OPENAI_API_KEY` 是首选官方配置；`OPENAI_FALLBACK_BASE_URL`、`OPENAI_FALLBACK_API_KEY` 保留原生图接口及原密钥。只作用于生图子进程，不修改聊天、Codex 或全局环境。

首选始终先用；明确失败且未返回结果时可切换一次备选，保持本技能的 `gpt-image-2.5-sunburst / high`、提示词和参考图。模型名是既有服务标识，不保证官方支持；官方明确不支持时使用备选，不擅自改型号。参数错误先查参数，安全策略拒绝不切换绕过。超时、连接中断、5xx 或结果不确定时先检查产物，不能自动跨服务重发可能已计费的请求。备选也失败时停止并报告脱敏错误。

每次只把选中服务的一组地址与密钥成对映射到 CLI 子进程的标准 `OPENAI_BASE_URL`、`OPENAI_API_KEY`，不改写磁盘首选字段。记录实际服务标识并告知切换，不输出密钥。

## 本地.env

建议采用以下变量名；下面仅说明格式，不是有效凭据：

```dotenv
# 填入服务商给出的API基础地址，不是网页控制台地址。
OPENAI_BASE_URL=
# 填入用户的API Key，仅保存在本地。
OPENAI_API_KEY=
```

真实配置仅在本地及用户授权主机保存；按实际文件加载；若现有文件采用不同变量名，可在进程内映射这两个值，不强制用户重命名或修改已有文件。

## 查找与加载

1. 用户指定本地 `.env` 路径时，使用该路径；否则依次检查当前工作区根目录的 `.kaltsit-imagegen.env`、`.env`，再检查 `~/.codex/skills/ui-art-generation/.env`；Unity仓库通常是仓库根而不是嵌套的Unity工程根。
2. 未找到时，只检查当前任务已有记录中明确指向的配置位置；仍缺失时询问文件位置。多个候选且服务不同，只询问采用哪个，不读取无关目录中的密钥文件。
3. 仅提取所需字段，不将文件内容、密钥、认证头或含密钥的URL打印到工具输出。可以报告“已找到文件、所需变量已配置”，不输出值。
4. 将解析后的值传入启动CLI的子进程环境：`OPENAI_API_KEY` 与 `OPENAI_BASE_URL`。不要假设CLI自动读取工作区 `.env`，也不要把密钥放在命令行参数里。
5. 优先用现有dotenv解析库处理引号、注释和等号；没有时只做满足该文件语法的最小解析。不要把 `.env` 当Shell/PowerShell代码执行，不使用命令替换或 `Invoke-Expression`。

服务地址应为该供应商要求的SDK/API基础地址。例如服务商可能要求以 `/v1` 结尾；不要不经核实就追加或删除路径，也不要把 `/images/generations`、`/images/edits` 这样的完整操作端点当成基础地址。

配置文件存在但字段为空时，提示用户在本地补齐具体变量；不要让用户把完整Key粘贴到对话里。文件未提供期间继续准备素材清单、参考图和最终提示词，等配置可用后再执行依赖API的步骤。

## 调用要求

阅读当前 `imagegen` 的CLI文档和帮助，以实际支持的参数为准。生成与编辑均显式传入 `--model gpt-image-2.5-sunburst --quality high`，并使用用户配置的服务地址及Key；不修改官方CLI、不另写SDK生图客户端。

`generate` 适用于新物件，`edit` 适用于保留轮廓的改色、补绳和覆盖布制作。用提示词文件保存最终提示词，输出写到独立工作目录，再挑选正式资源。

透明输出必须同时核实当前模型、服务与CLI的参数支持；不能仅因旧会话成功就假设所有端点接受 `background=transparent`。不支持时报告限制和可行后续处理，不为获得透明度自行切换模型。不要未经检查用颜色阈值抠图，损伤黑色实体、孔洞或细绳。

执行失败时，核对状态码、模型和参数是否受支持即可；日志需去掉认证信息。请求尺寸与返回尺寸分别记录；发请求前检查可接受的尺寸，不把长梁的最终裁切比例直接当作请求限制。

## 配置保护与交付记录

`.env` 不复制进技能包、正式美术资源目录或制作说明，不加入Git暂存；需要记录来源时只记录本地文件位置和变量名。不要把设置写入全局用户环境，以免影响其他项目。

记录实际调用的模型 `gpt-image-2.5-sunburst`、质量 `high`、提示词、尺寸与结果路径。服务地址如确需记录，只使用不含认证信息的标识；不要保存Key、请求头或原始环境文件。
