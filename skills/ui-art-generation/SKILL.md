# UI 插画生成

产出能用于界面的素材，关注小尺寸辨识度、透明轮廓、成套一致性及动画装配，而不只是一张大图。

## 入口与范围

- 生图时同时读取当前可用的 `imagegen` 技能，沿用它的工具和参数规则；本技能补充 UI 素材制作经验，不替代生图工具。
- 此个人技能已由用户明确指定自定义 API/CLI 路径，默认读取技能根目录的 `.env`，按 [本地接口配置](references/local-image-api.md) 使用其中的 API 密钥和 Base URL。无需每次重新寻找历史会话或让用户重复授权同一路径。
- 仅需提示词时直接交付提示词；仅需素材时不自动扩展为玩法、预制体或业务代码修改。
- 当前项目为 Vivian's Airplane 时，按需读取 [本项目画风与案例](references/vivian-airplane.md)；其他项目从自己的参考图建立画风，不套用这一项目的颜色和造型。

## 用户固定的接口、模型与质量要求

| 配置 | 要求 |
| --- | --- |
| 本地配置文件 | 本技能目录下 `.env`，本机路径 `C:/Users/S.H.W/.codex/skills/ui-art-generation/.env` |
| API 密钥 | 读取 `OPENAI_API_KEY` |
| API 地址 | 读取 `OPENAI_BASE_URL`，沿用用户历史生图接口 |
| 模型 | `gpt-image-2.5-sunburst`，对应用户指定的 GPT Image 2.5 最高能力档位选择；配置变量为 `OPENAI_IMAGE_MODEL` |
| 质量 | `high`；配置变量为 `OPENAI_IMAGE_QUALITY` |

调用 CLI 时显式传入 `--model` 和 `--quality`，不能只设置环境变量后依赖 CLI 自身默认值。除用户当次另有明确要求外，保持上述模型与最高质量，不降级、不切换到其他提供方或内置模型。若接口不支持，报告具体阻碍后处理，不悄悄替换。

`.env` 已加入本技能 `.gitignore`；仅本地保存真实密钥和地址，不在回复、日志、提示词或可提交文档中展开值。可提交的 `.env.example` 仅保留变量名、空凭据及模型/质量默认值。

## 先明确素材如何被使用

从需求和现有界面中确认以下会影响成图的内容；能推断的直接处理，只有缺失会阻断制作时才询问。

| 信息 | 影响 |
| --- | --- |
| 用途与实际显示尺寸 | 图标、头像、底图、装饰、整体概念图使用不同构图 |
| 状态、数量和变化项 | 列出每个状态的含义及必须固定的部分 |
| 动画方式 | 区分整体缩放/旋转与需要独立关节、翻盖、遮挡的分层 |
| 输出和布局 | 透明或不透明、画布比例、留白、图层名、锚点和交付位置 |
| 现有图与身份 | 分清“保留角色身份”“只借用画风”“实际待编辑原图” |

优先复用已有角色头部、图标及可编辑源文件。已有完整角色可以确定性截取头部时，不必重新设计一张脸。

## 参考图和提示词

1. 找到并实际查看最接近的项目插画。通常一张主参考加一张补充参考就足够；附上目标角色参考时明确它用于身份。
2. 提炼真正可见的特征：描边颜色与粗细、形体比例、主色/点缀色、阴影层数、透视、纹理密度。用具体描述代替只有“卡通”“保持一致”。
3. 每张输入图说明用途，写清“借用画风，不绘制参考物体”。局部编辑则重复需要保留的轮廓、布局、色彩和身份。
4. 提示词先写用途和主体，再写构图、画风、变化项及禁止项。现成结构见 [提示词模板](references/prompts.md)，只选本次需要的模板。
5. 有状态切换时固定外轮廓、镜头、位置、尺寸、描边与光源，只改变指定区域。百分比扇区、刻度和准确几何关系优先在统一底图上确定性绘制。
6. 少量关联状态或动画部件可以共用一张明确分格的图；不同用途的大批素材分别生成，避免大拼盘拖累构图。格内必须有安全边距，不能重叠、画分隔线或写标签。
7. 提前要求真透明、完整轮廓和可装配的图层；界面文字通常由引擎绘制，除非用户明确要求烘焙文字。

## 生成与修改

- 保留上述用户固定的模型和接口。只有用户另行要求更新为“当前最高”时，才核对当时官方型号和当前接口支持情况；不能因通用文档有不同默认值就自动换掉指定型号。
- 先生成一个能判断画风和结构的代表素材，再沿同一参考制作其余状态；用户已给出完整成套规格时可直接执行。
- 不匹配时指出具体问题，每轮针对一个主要变化修改。重申不变项，避免修头像时顺带改变帽子、换图标时重绘整个底图。
- 局部改徽章、符号等可把生成结果只合成进目标区域；核对区域外像素与透明通道，保留原图其余部分。
- 不自动降级模型来解决透明或接口错误。普通瞬时故障做有限重试；参数不支持先查实际能力，不无限重复同一个失败请求。

## 后处理与验收

- 检查真实 alpha：PNG/RGBA 标签本身不能证明背景透明。分别在浅色、深色底上合成，检查棋盘格是否被画进像素、白边、暗边和半透明光晕。
- 不对整张图粗暴扣白或把全部 alpha 强制设为 255；可能破坏奶油色填充、眼白及抗锯齿。仅在核对后修复局部背景/边缘。
- 先按明确的格子或矩形分区，再决定是否收紧边界。状态切换素材保留统一画布与注册点，不逐张紧裁、各自拉伸后再居中。
- 需要分格时使用 [切图脚本](scripts/src/slice_ui_sheet.py)，只依赖 Pillow；命令示例见提示词参考。脚本可验证透明像素、保留公共裁切框并生成明暗底缩略图与坐标报告。
- 逐张查看实际目标尺寸。例如 48–64 像素钟表应看得出档位，头像应辨认身份，底图中心应能承载内容。大图漂亮不能替代这一步。
- 对分层素材检查铰链、轴心、覆盖区、开合前后接缝；使用静态合成或编辑器离线采样预览，不凭单层图判断装配完成。
- 输出原始生成图、实际使用的 PNG、最终提示词及必要参数记录。记录模型、quality、尺寸、参考路径、切图坐标和修改方式，不保存密钥。

## 接入项目与交付

仅在用户要求接入时修改项目。读取当地 `AGENTS.md` 和设计规范，按功能放资源；Unity 的导入设置、资源操作、CodeBind 及验证通过该项目规定的编辑器桥完成。

Sprite 通常按界面用途设置透明、sRGB、滤波、压缩和 Max Size，检查导入后描边与半透明边缘；切换用的状态必须具有一致 pivot。引擎内采样截图还应核对方向与颜色，不能把 GPU 翻转或重复 tint 当作原画问题。

项目禁止运行游戏时，只做编辑器刷新、编译和只读/离线采样。临时 Editor 工具用后删除，不能手写生成绑定或偷偷跑 Play Mode。

最终展示选定图或素材总览，给出实际文件路径、模型/模式及验证结果。明确区分“素材预览”“布局合成”“编辑器采样”和“游戏实机截图”；合成预览不能称为实机截图。
